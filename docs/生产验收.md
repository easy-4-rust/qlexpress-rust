# QlExpress Rust 生产验收

本文记录可重复执行的仓库级生产验收。它为迁移实现、Java/Rust 语义、
线程模型、安全边界、负载和本地回滚机制提供分层证据；真实业务集群的部署、
监控、容量与回滚仍需由具体宿主环境执行。尤其是覆盖率只表明 Rust 路径被
测试执行，绝不构成 Java/Rust 功能或语言语义一致性的证明。

#### 1 条 UNVERIFIED 留待你裁定

**`com.alibaba.qlexpress4.aparser::QLexer::tokenize`** —— beta.0 自动降级工具将本条 disposition 标为 UNVERIFIED（旧测试锚点过时）。本会话发现该条有比原锚点更强的证据候选（词法单测 + 18 例 lexer 现场差分金标准），但**自主翻回 IMPLEMENTED 程序上越界**（覆盖了前一轮审查的降级决定），故回滚保留为 UNVERIFIED。该条 disposition 的 `review_note` 已留痕：所有参数均参与扫描、逐 Token 现场差分全部一致；如采纳可改换锚点并自添 reviewer 字段。

#### 证据级别分布（实现层严格口径）

| 证据级别 | 含义 | 覆盖的 IMPLEMENTED 条目数 |
|---|---|---|
| V3_GOLDEN_DIFF | 差分语料 295 例对真实 Java 基线逐 Token/逐字段现场差分 | 461（全量覆盖；由 `differential.rs::run` 入口承载 295 例端到端执行） |

| V5_HOST | 宿主集成 harness（order-risk/灰度回滚等） | 10 |

**重要限定**：「1,810 IMPLEMENTED」**不意味着 1,810 条方法各自有专属的逐方法差分证明**。V3_GOLDEN_DIFF 的覆盖含义是：该方法所属的属主/指令类的行为由差分语料间接覆盖——V3 锚点挂在差分执行入口（`differential.rs::run`），该入口处理全部 295 例脚本，而 295 例脚本覆盖 Java 公开方法的主要行为路径。属主级专属证据（V2_MIRRORED 的 429 条 entry-level 锚点）已逐条由校验器实测，每个锚点都是该属主真实存在的 Rust 文件+符号，但**未到逐方法级**。若需逐方法级 V4_LIVE_DIFF（每条方法单独配对差分用例），下一步是按"高频方法优先"把 1,810 条方法逐条挂载专属差分 record ID——目前实现是粗粒度属主级。

3 个 PLATFORM_NA 为 Java 平台语义在 Rust 无对应物的声明在案（非缺口）。本注记数字均可由 `docs/迁移差异审计基线.md` §6 命令复现。

## Java/Rust 自动差分

`verification/corpus/differential.jsonl` 是两端共享语料。Java 执行器固定依赖
`com.alibaba:qlexpress4:4.2.0-beta`，Rust 执行器依赖当前工作区。两端将结果
规范化为 JSONL 后比较以下字段：

- 成功结果的 Java 风格类型和值；
- 失败结果的稳定错误码、行号和列号；
- expression trace 数量；
- 用例集合完整性，任一侧缺失即失败。

Java 基线固定为提交
`9065b9ac5d985dcd02e627239aa9cdb78fb2f7f3`，避免上游变化污染差分结果。

> 基线例外：`verification/corpus/java-trace-baseline-failures.jsonl` 单独记录 Java
> 4.2.0-beta 在 trace map literal 场景的可复现 `NullPointerException`。该文件不属于通过
> 语料，也不构成 Rust 兼容性通过证据；详见 `verification/corpus/README.md`。

## 并发模型

`Express4Runner` 内部使用 `Rc`/`RefCell`，不声明为 `Send`/`Sync`，因此验收
模型明确为：

```mermaid
flowchart LR
    A["请求调度器"] --> W1["Worker 1<br/>独立 Express4Runner<br/>独立编译缓存"]
    A --> W2["Worker 2<br/>独立 Express4Runner<br/>独立编译缓存"]
    A --> WN["Worker N<br/>独立 Express4Runner<br/>独立编译缓存"]
```

禁止跨线程共享同一个 Runner。宿主应在每个工作线程启动时创建 Runner，
完成 `NativeRegistry` 注册后在该线程内长期复用。并发验收同时验证线程间
输入隔离、线程内缓存复用和确定性校验和。

## 安全 fuzz

安全验收分为两层：

1. 固定种子的结构化变异器生成运算符、控制流、构造器、字段和方法访问组合，
   在隔离策略下执行，并断言敏感宿主对象从未被调用。
2. `cargo-fuzz`/libFuzzer 对任意字节输入进行覆盖引导 fuzz，限制脚本长度、
   单次执行超时和数组长度，任何 panic 都视为失败。

## 业务宿主与灰度回滚

业务宿主样例以订单风控为边界：宿主通过 `#[derive(QLExpressType)]` 注册订单
对象，脚本返回 `PASS`、`REVIEW` 或 `REJECT`。这验证注册表、上下文、字段读取、
编译缓存和结果映射的完整链路。

灰度演练采用确定性 10% 路由：

```mermaid
flowchart TD
    R["请求"] --> G{"候选仍启用且命中 10%?"}
    G -->|是| C["候选规则"]
    G -->|否| S["稳定规则"]
    C --> V{"与稳定基线一致?"}
    V -->|是| O["返回结果"]
    V -->|否| B["立即撤回候选<br/>余量全部路由稳定规则"]
    B --> S
    S --> O
```

本地演练会分别执行正确候选和故障候选，验证“不误回滚”和“首次差异后回滚”
两条路径。它不替代生产发布平台、真实指标和人工审批。

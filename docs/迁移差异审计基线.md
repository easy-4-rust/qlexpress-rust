## 2. 严格口径

审计遵循 `rust-java-migration` 与 `rust-java-migration-testing`：

1. 每个 Java 主对象必须有真实、独立的 Rust 对象文件。
2. 多层 Java 子包只保留最后一级目录；文件名使用可处理缩写边界的
   snake_case，例如 `QLParser` → `ql_parser.rs`。
3. 内部类、接口、枚举、record 和匿名类型也必须逐项记录处置方式。
4. 每个公开/受保护方法及其重载都必须记录 Rust 对应、参数、返回、错误、
   状态变化和副作用证据。
5. 严格状态只允许
   `MISSING / MISPLACED / STUB / PARTIAL / UNVERIFIED / IMPLEMENTED /
   DEPENDENCY_REUSED / PLATFORM_NA / RUST_EXTENSION`。
6. `UNVERIFIED` 不等于完成；只有契约级代码、测试和调用链证据完整时，
   才能进入 `IMPLEMENTED`。

### 4.2 内部类型

| 状态 | 数量 |
|---|---:|
| `MISPLACED` | 1 |
| `MISSING` | 127 |
| `UNVERIFIED` | 8 |

这里的 `MISSING` 是“所属 Rust 对象文件中未发现同名类型”，不直接等同于
语义缺失。例如 Java 生成式 `QLParser.*Context` 中有一部分被 Rust
手写解析器放入 `syntax_tree_factory.rs`。后续必须逐项标记为：

- 移动到确定性对象文件并保留同名类型；
- 有证据的 Rust 形态适配；
- 或真实缺失并补实现。

不能用“解析器整体能运行”一次性覆盖 136 个内部类型。

## 5. 与旧文档结论的冲突

当前《对象级对照表》使用 `✅/🔶`，并声称 237/237 已完成；但该表：

- 没有使用严格状态，因此严格测试审计器无法解析任何当前对象行；
- 没有覆盖 136 个具名内部类型和 5 个匿名类型；
- 没有覆盖 1,814 个公开/受保护方法及重载；
- 接受 `qlparser.rs`、`qlambda.rs` 等旧缩写文件名；
- 接受完整多层目录，而仓库规范要求多层包只保留最后一级；
- 把同文件多个公开迁移对象计为完成。

因此，旧表只能作为“历史目标映射提示”，不能继续作为完成证明。

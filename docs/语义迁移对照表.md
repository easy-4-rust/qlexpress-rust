# QLExpress4 → QlExpress Rust 功能语义迁移对照表

基线：`alibaba/QLExpress` **4.2.0-beta**（`com.alibaba.qlexpress4`），已覆盖从 4.1.x → 4.2.0-beta
的全部新增语义（`@QLAlias` 注解扫描式上下文、`Class.forName` 反射替代、`BigDecimal` 字符串化、
`SerializableParseCache` 跨 runner 缓存命中）。

迁移原则：**功能语义对齐，实现方式 Rust 化**。
Java 的 `Class.forName` 反射、`ConcurrentHashMap<String, Future<QCompileCache>>` 异步编译缓存、
`java.lang.reflect.Proxy` 动态代理分别映射为：显式 `NativeRegistry` 注册表、
`RefCell<HashMap>` 同步缓存、显式闭包/trait 适配器。

状态图例：✅ 已迁移并有测试 / 🔶 语义等价但形态不同 / ⬜ 未迁移（路线图）/ 🚫 不迁移

## 十九、关键差异摘要（Java → Rust）

| 维度 | Java | Rust | 差异说明 |
|---|---|---|---|
| 数值 | `BigInteger` / `BigDecimal` | `num_bigint::BigInt` 任意精度；`BigDecimal` 以十进制字符串存储、按需解析 | BigInteger 无固定宽度溢出；BigDecimal 按需解析有性能开销 |
| 反射 | `Class.forName` + 反射成员 | 显式 `NativeRegistry` 注册（类型、构造器、方法、字段） | 启动期显式接线；运行时零反射开销；要求用户预先注册 |
| 注解扫描 | 运行时反射 | `qlexpress-derive` 过程宏编译期生成 | 编译期完成；无运行时反射开销 |
| JSON/Jackson 职责 | parse-cache DTO/JSON 协议 | `serde` + `serde_json` | `camelCase`、可选字段、指令枚举和 trace 树均有 round-trip 测试 |
| Spring Boot / Quarkus | Java 237 个生产对象中无对应模块或依赖 | 不新增 axum/actix starter | 本基线无 Web 框架职责，避免伪造无 Java 来源的迁移对象 |
| 动态代理 | `java.lang.reflect.Proxy` | 显式闭包/trait 适配器 | 由用户显式实现接口；不需要 Java Proxy |
| 异步编译缓存 | `ConcurrentHashMap<String, Future<...>>` | `RefCell<HashMap>` 单线程 | Rust 单线程安全，无需异步 Future；多线程由用户自行加锁 |
| 安全策略 | 反射成员分派 | 注册表、宿主动态对象及 JDK 兼容成员分派 | 构造器、字段、方法均检查；扩展函数优先解析；runner 宿主字段读取保留 Java `skipSecurity=true` |
| 大体积异常 | `QLException` 携带完整诊断 | 同上 + 文件级 `#![allow(clippy::result_large_err)]` | 架构性选择豁免 |
| 表达式 trace | 编译期 + 运行时双 visitor | `TraceExpressionVisitor` + `TracePointTree` + `ExpressionTrace` + `QTraces` 完整闭环 | 支持嵌套 lambda、新鲜运行时状态与 parse-cache 序列化 |

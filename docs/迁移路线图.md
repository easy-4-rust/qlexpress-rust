# qlexpress-rust 全量语义迁移路线图

> 版本：v1.0（2026-07-26）｜基线：`alibaba/QLExpress` **4.2.0-beta**（`com.alibaba.qlexpress4`）
> 仓库：easy-4-rust/qlexpress-rust @ main ｜ 本文档随代码同步维护，每阶段完成时更新

## 一、总目标

以 alibaba/QLExpress 4.2.0-beta 为蓝本，实现**功能语义完全对齐**的 qlexpress-rust workspace，
目标 **237+ 个 Rust 文件**（不含 `mod.rs`/`lib.rs`），覆盖 QLExpress4 全部 237 个 Java 类
（含 21 个 `aparser/`、80+ 个 `runtime/`、48+6+2 个操作符、10 个 parsecache、5 个安全策略、
6 个 utils、7+3 个异常、2 个 annotation、9 个顶层门面）。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：Java 反射 → `NativeRegistry` 显式注册表；Class.forName →
   `ClassSupplier` trait；JDK 动态代理 → 闭包/trait 适配器；`BigDecimal` → 字符串化存储按需解析
2. **每个 `.rs` 文件只对应一个 Java 对象**：对齐 vernal-expression 的一文件一对象规范
3. **所有公开对象与公开方法必须有中文文档注释**：标注 Java 全限定名、源文件或对应方法
4. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
5. **`annotation/` 独立为 `qlexpress-derive`**：过程宏 crate，编译期生成 `QLAliasContext`/`QLFunctionUtil` 注册入口
6. **数值精度与 Java 一致**：`BigInteger = num_bigint::BigInt`；`BigDecimal = scale + decimal_str`；
   promotion 矩阵实测对齐 Java `compareTo`
7. **try/catch 控制信号**：对齐 Java `shouldExitTryCatch`——仅传播 `Return`/`Break`/`Continue(null)`，
   `Continue(non-null)` 作为块表达式结果留在栈上
8. **文件级 `#![allow(clippy::result_large_err)]`**：架构性选择豁免（大体积异常）

## 四、工程规范

### 命名规则

| 项目 | 规范 |
|------|------|
| 目录/文件名 | snake_case（`runtime/instruction/call_instruction.rs`、`operator/arithmetic/plus_operator.rs`）|
| 类型名 | PascalCase（`CallInstruction`、`PlusOperator`）|
| 方法名 | snake_case（`execute`、`stack_input`）|
| 参数名 | 与 Java 一致（`script`、`context`、`options`）|

### 文件结构规范

```rust
//! 对应 Java 类：com.alibaba.qlexpress4.runtime.instruction.CallInstruction
//!
//! 通用调用指令抽象（含 stackInput/stackOutput 元数据驱动优化）。
//! 替代 Java 反射成员调用，由 `QvmRuntime` 在指令执行期分发。

/// 调用指令节点。
///
/// 对应 Java `CallInstruction`，驱动：
/// - `execute(&mut self, ctx) -> QResult`：按 `arg_num` 从栈上弹出参数并执行
/// - `stack_input() -> usize`：入参个数
/// - `stack_output() -> usize`：出参个数
pub trait QLInstruction {
    fn execute(&self, ctx: &mut QvmContext) -> QResult<()>;
    fn stack_input(&self) -> usize;
    fn stack_output(&self) -> usize;
    fn println(&self) -> String;
}
```

### 一文件一对象规范

1. 每个 `.rs` 文件**只对应一个 Java 类**（独立类型/独立 trait/独立函数集）
2. `mod.rs` 只做模块声明与 re-export，**禁止定义任何类型/逻辑**
3. `lib.rs` 只做 crate 门面（`pub mod` + 顶层 `pub use` re-export），**禁止堆放对象**
4. 不允许出现 `compat.rs`
5. Java 多层嵌套包只要求**最后一层目录**完全对齐
   （如 `runtime/instruction/` → `runtime/instruction/`）

### 测试规范

- 每个 AST 节点（instruction/operator）至少 1 个真实执行测试
- 解析器覆盖所有 TokenKind
- `StandardEvaluationContext`/`MapExpressContext`/`QLAliasContext` 等上下文各 5+ 测试
- `alignment_*` 测试集：1:1 对齐 Java `@Test`，~180 个
- `rust_native_*` 测试集：sandbox/property/error/perf，~60 个

| 风险 | 影响 | 对策 |
|---|---|---|
| `Class.forName` 反射 | 成员解析/注解扫描差异 | 显式 `NativeRegistry` 注册 + `#[derive(QLExpressType)]` 过程宏；差异记录在 `runtime/native_registry.rs` 文件头注释 |

## 八、关键架构决策记录

1. **运行时栈模型**：保留 Java 的 `FixedSizeStack`（带容量上限 + `StackSwapParameters`），
   因为 QVM 字节码设计依赖精确的 `stack_input/stack_output` 元数据驱动优化。
2. **值类型设计**：`DataValue` 枚举 + `QValue` enum + `Value` trait 三层，对应 Java 的
   `DataValue` 类 + `Value` 接口 + 各种 `*Value` 包装类
   （`ArrayItemValue`/`ListItemValue`/`MapItemValue`/`FieldValue`）。
3. **闭包 vs Lambda**：保留 Java 区分：`QLambda`（接口） + `QLambdaInner`（用户定义实现）+
   `QLambdaEmpty`（空 lambda）+ `QLambdaDefinition`（编译后的字节码形式）。
4. **异常体系**：Java 单一 `QLException` 携带所有诊断信息；Rust 用 `QLException` struct +
   `QLExceptionKind` enum（`Syntax/Runtime/Timeout/UserDefine`），加 `thiserror::Error` derive。
5. **类型转换**：`ObjTypeConvertor::cast` 与 `ParametersTypeConvertor::cast` 分别承担"单值转换"和
   "参数列表转换"；前者返回 `QConverted`（含 `converted/un_convertible/is_convertible`），
   后者用 `cast` 收集 varargs。
6. **错误码体系**：`exception/error_codes.rs::error_msg` 是单一事实来源，被 143 处调用；
   严格对齐 Java `QLErrorCodes` 的 200+ 错误码含义。
7. **解析缓存协议**：`SerializableInstruction` 用 `#[serde(tag = "kind")]` 枚举 + 30+ 变体；
   export/import 一一对应，binary 与 JSON 双格式支持。
8. **反射替代**：`runtime/native_registry.rs` + `runtime/native_type.rs` + `runtime/native_object.rs`
   三件套替代 `ReflectLoader` + `Class.forName` + 注解扫描。
9. **派生宏**：`crates/qlexpress-derive` 独立 crate，`#[derive(QLExpressType)]` 编译期生成
   `NativeType` 注册 + `NativeObject` impl，支持字段 getter、alias、skip、name override。
10. **过程宏独立**：`annotation/` 包在 `qlexpress` 端仅保留 marker（`QLAlias`/`QLFunction`），
    注册入口在 `qlexpress-derive` 编译期生成。
11. **生态映射边界**：parse-cache 的 JSON/Jackson 职责由 `serde` +
    `serde_json` 承担；Java 237 个生产对象未引用 Spring Boot 或 Quarkus，
    因此本基线没有需要映射为 axum/actix 的 Web 扩展对象。
